## ☁️ AWS Cloud Security Projects

### 🔐 Project 1 — Root Account Monitoring with CloudTrail & SNS
> **Stack:** CloudTrail · EventBridge · SNS · IAM · KMS

Built a real-time root account detection pipeline for an AWS account. Configured a multi-region CloudTrail trail with SSE-KMS encryption and log file integrity validation. Authored an EventBridge rule targeting `ConsoleLogin` events where `userIdentity.type = Root` and piped matches to an encrypted SNS topic — achieving sub-60-second alert latency. Enforced CloudTrail tamper protection via IAM deny policies aligned with **CIS AWS Benchmark 3.3** and **NIST AC-6**.

📄 [Read the full case study →](https://attacker-codeninja.github.io)

### 🔎 Project 2 — IAM Misconfiguration Detection & Remediation
> **Stack:** IAM · IAM Access Analyzer · AWS CLI · Security Hub · CloudShell

Conducted a full IAM security audit across a test AWS account. Generated and analysed IAM Credential Reports to surface users without MFA, stale access keys (90+ days), and dormant console accounts. Used `GetAccountAuthorizationDetails` to detect inline wildcard `*:*` policies. Deployed IAM Access Analyzer in all enabled regions to identify externally shared S3 buckets, IAM roles, and KMS keys. Mapped privilege escalation paths (`iam:PassRole`, `sts:AssumeRole`) to MITRE ATT&CK techniques **T1078.004** and **T1098**, with documented PoC attack chains and full remediation report.

**Misconfigurations Found & Remediated:**
```
✅ MFA not enforced for console users          → IAM Deny policy with aws:MultiFactorAuthPresent
✅ Inline wildcard *:* policy on dev user      → Replaced with scoped managed policy
✅ Access key active for 150+ days             → Rotated and old key deactivated
✅ sts:AssumeRole trust with no conditions     → Added ExternalId + MFA condition
✅ iam:PassRole + ec2:RunInstances priv-esc    → Scoped to specific role ARN + service
✅ Public KMS key policy (Principal: *)        → Restricted to specific IAM principals
✅ Weak password policy (min 6 chars)          → Updated to CIS Benchmark standards
```

📄 [Read the full write-up →](https://manieshneupane.com.np)

### 🛡️ Project 3 — GuardDuty Threat Detection & Security Hub Integration
> **Stack:** GuardDuty · Security Hub · EventBridge · CloudWatch · SNS · CloudTrail

Enabled Amazon GuardDuty with S3 Protection and CloudTrail data event monitoring across all active regions. Reviewed and classified real findings by MITRE ATT&CK Cloud tactic. Integrated findings into AWS Security Hub with the **AWS Foundational Security Best Practices (FSBP)** standard enabled — surfaced 23 failed controls across IAM, S3, and CloudTrail. Built an EventBridge rule triggering SNS alerts on findings with severity ≥ 7.0, and added a secondary CloudWatch Logs metric filter on `UnauthorizedOperation` API errors as an independent detection layer. Aligned the full pipeline to **NIST CSF Detect (DE.CM)** and **Respond (RS.CO)** functions.

**GuardDuty Finding Types Analysed:**
```
🔴 Recon:EC2/PortProbeUnprotectedPort          → T1595 Active Scanning
🔴 UnauthorizedAccess:IAMUser/ConsoleLogin.B   → T1078.004 Cloud Accounts
🟠 Policy:S3/BucketBlockPublicAccessDisabled   → T1562 Impair Defenses
🟠 CryptoCurrency:EC2/BitcoinTool.B            → T1496 Resource Hijacking
```

📄 [Read the full write-up →](https://manieshneupane.com.np)

### 🪣 Project 4 — S3 Bucket Security Audit
> **Stack:** S3 · IAM · AWS CLI · ScoutSuite

Audited S3 bucket configurations using AWS CLI (`get-bucket-acl`, `get-bucket-policy`, `get-public-access-block`) and ScoutSuite across a test AWS environment. Identified and remediated a public `Principal: *` bucket policy, disabled `BlockPublicAcls` setting, and two buckets missing default encryption. Aligned all findings to **NIST SP 800-53 SC-28** and **CIS AWS Benchmark 2.1**. Enabled S3 server access logging and object versioning post-audit, then ran a second ScoutSuite scan to validate a clean security posture.
